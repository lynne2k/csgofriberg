# 旧库直接用于队友游戏

2026-10-10 按用户确认的最小需求：使用旧 GitHub 数据中每张地图的两组五人名单和原有 HLTV 地图链接。每组五人两两组成队友关系；不再要求每张地图重新抓取十个 HLTV 数字编号。

## 生成与使用

在仓库根目录运行：

```sh
python3 scripts/cslink_legacy_import.py
python3 scripts/local-mac.py stop
python3 scripts/local-mac.py start
node scripts/cslink_local_route_smoke.mjs
```

生成 `.local-data/cslink/legacy-relations-v1/graph.json` 和 `report.json`。启动脚本自动加载到 `/teammates` 关系查询和 `/teammates/practice` 练习，两处使用同一份导入数据。更新原始库或身份映射后重跑即可；无需联网采集。

## 保留的最小规则

- 范围继续使用已整理的 A/S 赛事清单。原始来源为固定提交的 `tedtay/CS-GO-Pro-Matches-Comprehensive-Dataset`。
- 同一对选手只建立一条关系，重复比赛作为额外来源链接保存。同一地图重复不多算一次出场，也不会增加路径跳数。
- 五人统计组本身提供同队证据。旧统计组与比赛列表的队名次序可能相反，因此页面展示整场双方比分，不凭次序猜这组五人属于哪个队名。
- 昵称保持大小写。`NiKo` 和 `niko` 是两个身份。可由现有出场记录确认的身份复用现有编号；来自旧数据的映射按导入来源展示，不冒称重新抓取或人工复核。
- 无法确定真实身份的昵称使用赛事和五人名单限定的内部编号，照常保留该组队友关系和地图链接；不会与其他赛事的同名者强行合并。这些局部身份可能分开了实际同一个人的不同出场，后续可按证据合并。
- 2026-10-11 起按“能用就导”逐组判断：只要地图有冻结的 HLTV 链接，某一组有 5 个不同昵称（大小写敏感）就导入这一组的两两关系；另一组缺人、超过 5 人或组内重名时只丢那一组，并记入 `report.json` 的 `droppedGroups`。Liquipedia 比分/地图名不一致、HLTV 复抓失败等只作为地图的 `sourceWarnings`，不再挡住名单。
- 两组出现同一昵称时（如两个不同的 `steel`），只要解析出的身份不同就照常导入、互不连线；若两组解析到同一个人，同一赛事其他地图能印证完整五人名单的一侧保留，另一侧丢弃；都无法印证时两侧该昵称改用按名单区分的内部编号。
- 真正无法使用的地图（旧库没有任何名单行、链接与冻结记录不符）保留在 `excludedMaps` 并写明原因。
- 已有 HLTV 抓取和人工复核记录优先，同一地图的旧库导入不会覆盖它们。

`report.json` 记录导入数、去重关系数、内部身份数、隔离原因和输入来源。地图记录数不能当成不同队友关系数；多场比赛常常重复证明同一关系。

## 验证

Python 测试验证分组、大小写身份、同名冲突和重复关系。服务端测试验证导入、关系查询、最短路径和练习使用同一批数据；实际路由检查同时验证既有 jks/rain 地图证据和新导入内部身份的直接队友路径。2026-10-10 路径房间已复用这份综合关系图，入口 `/teammates/duel`。

2026-10-11 本地结果（版本 `83b37f5e05d9ca8ae2ea`）：旧库导入 11,260 张地图（原 11,213，新增 47 张原先被排除的图，全部两组都可用），A/S 清单共覆盖 11,861 / 11,882 张。仍排除 21 张：旧库对这些地图只有比赛元数据、没有任何选手行（`quarantined_structure_no_old_roster_rows`）。另有 598 张已由历史 HLTV 抓取、3 张已由人工复核覆盖，不重复导入。合并所有来源后共 12,687 张不同地图、11,673 对队友关系；导入本身有 8,815 对，856 条内部身份。
