## 值得接着做，但不是本次已确认的新 bug

| 优先方向 | 原因与建议验收 |
| --- | --- |
| 可重复的发布与数据移交 | Git 缺大文件；旧 deploy 脚本带历史日期。做清晰发布 manifest、暂存校验和回滚流程，再考虑自动化 |
| 访客转登录账号的 CS Link 成绩迁移 | 旧站有账户机制，不代表每日 Redis 和天梯 JSON 的身份迁移已打通；先沿调用链和测试确认，不直接重做登录 |
| 空房/离线玩家的多轮收尾 | 历史曾观察到全员未完成的房间长期轮转；当前还需针对 AFK、两人断线、房主离开、局间重连复测，不能凭现象判定已修或必现 |
| 热度与难度持续维护 | 脚本使用人工置顶和写死年份；补录后分数覆盖比身份少。审查简单池是否符合近期一线认知，不以地图数冒充人气 |
| 前后端身份/筛选一致性 | 客户端存在照片折叠和活跃筛选；服务端完整图更广。测试“能在本地连上但提交拒绝”、最短路线含不可搜索人物等边界 |
| 数据覆盖与球队标签 | 首图采样会漏替补，队伍不是实时信息；补用户指出的真实遗漏优先于无目标重抓整库 |
| B 级赛事扩库 | 已有试点文件，尚不能据此认定整批上线。先核对完成/缺页/耗时、五人阵容、来源和新增关系，再决定扩大 |
| 性能与移动端回归 | WebP 已上线，但没有本次负载测试结论；不要凭 2 核/2 GB 规格承诺几千人在线。测实际慢点、键盘/触摸、资源缓存 |
| 文档/脚本旧注释 | 当前接手文档已说明差异，后续按模块逐步同步旧注释和 README；不要无授权清理原站或重写整库 |
